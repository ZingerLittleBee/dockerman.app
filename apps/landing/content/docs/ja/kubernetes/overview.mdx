Dockerman の Kubernetes サポートは、ツールを切り替えたり新しいダッシュボードを学習したりすることなく、実際の Kubernetes クラスターを実行して確認するための、軽量で GUI ファーストな方法です。

## DockermanでKubernetesを使う理由

すでに Docker で使っている同じアプリで Kubernetes も扱いたいときに使ってください。インターフェースをローカルかつ高速に保ち、k3d であればワンクリックでクラスターを用意でき、別のダッシュボードへ移ることなく、Rust と Tauri のネイティブデスクトップアプリ内で作業できます。Docker Desktop 付属の Kubernetes より軽量で、ローカル開発、小規模クラスター、CI の健全性確認に適しています。

## クラスター概要ダッシュボード

Kubernetes の概要を開くと、クラスターのライブサマリーが出ます。

- **CPUとメモリカード** — クラスター全体の使用状況を見出しカードとして表示します。対象クラスターに `metrics-server` が必要です。
- **ワークロードカウント** — 実行中および保留中の Pod、Deployment、Service、その他のリソースを、アクティブなネームスペースだけでなく**すべてのネームスペース**にわたってカウントします。
- **ノードステータス** — ノード数と Ready 状態を一目で確認できます。
- **最近のイベント** — 最新のクラスターイベントと、完全な[イベント](/ja/docs/kubernetes/events)ブラウザへのリンク。

個別のリソースを開く前の出発点として、ダッシュボードを使ってください。

## マルチクラスター切り替え

Dockerman はアクティブな Kubernetes クラスターを **アクティブな Docker ホストとは独立して**追跡します。クラスターを切り替えても、可能な限り現在の K8s ページが残り、アプリ再起動後にディープページ（CRD インスタンス、YAML エディタ）が戻り、ネームスペースセレクタが新しいクラスターに合います。再接続すると最後に見ていたリソースが戻るので、作業場所を失いません。

## ネームスペース

トップバーのネームスペース切り替えで、Kubernetes の各一覧の範囲を決めます。クラスターから切断せずにネームスペースを変え、新しいネームスペースでワークロード、ネットワーキング、設定、RBAC を見続けられます。

## サイドバーのカスタマイズ

Kubernetes サイドバーは Cluster、Workloads、Service & Network、Config & Storage、Access Control、Helm、Tools の 7 グループです。

- **グループごとのデフォルト展開状態** — クラスターに接続したときに自動的に開くグループを選択できます。ランタイムの折りたたみ状態とは独立しています。
- **項目ごとの可視性** — 使用しないリソースエントリを個別に非表示にできます。ランタイムの展開/折りたたみ状態は次回セッションでも維持されます。

両方とも[設定 → サイドバー](/ja/docs/reference/settings#サイドバー可視性コントロール)から編集します。

## 権限エラー

リストは型付きの `K8sListResult<T>` を返すので、`403 Forbidden` はページ全体を落とさず **そのリスト自身に**出ます。どのリソースにアクセスが無いかが分かるので、RBAC を直しているあいだもクラスターの残りは使えます。

## まだサポートされていない機能

<Callout type="info">
  以下のワークフローはまだ範囲外です：

  - k3d以外のクラスター作成（kubeadmやマネージドサービスのプロビジョニングなど）。
  - Ingress以外のGateway API。
  - ビジュアル CRD エディタ。代わりに YAML 編集を使ってください。
  - ビジュアル NetworkPolicy エディタ。YAML で作成してください。
</Callout>
