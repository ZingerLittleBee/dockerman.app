チャートリポジトリとリリースを、アプリ内の Helm から管理します。

Dockerman は初回使用時に Helm バイナリを自動でダウンロードして管理し、SHA-256 チェックサムを検証します。Helm を別途入れる必要はありません。

## リポジトリ

よく使うリポジトリを追加し、最新のチャートインデックスが必要になったら更新してください。

<Steps>
  <Step>
    ### リポジトリを追加

    リポジトリ名とURLを入力します。例えばBitnami、Jetstack、ingress-nginxなどです。
  </Step>
  <Step>
    ### リポジトリを更新

    リポジトリを追加または変更した後、チャートインデックスを更新します。
  </Step>
  <Step>
    ### リポジトリを削除

    Dockermanで不要になったリポジトリは削除してください。
  </Step>
</Steps>

## チャートを参照

追加したリポジトリのインデックスを検索してチャートを選びます。埋め込み README や完全なバージョン一覧は保証しません。

## リリースをインストール

<Steps>
  <Step>
    ### チャートとバージョンを選択

    リポジトリの結果が出すチャートを選び、インストール前に実効バージョンを確認します。
  </Step>
  <Step>
    ### リリース名とネームスペースを設定

    インストール前にリリース名と対象ネームスペースを設定します。
  </Step>
  <Step>
    ### values.yamlを編集

    Dockermanはチャートのデフォルト値をMonacoに読み込み、必要な値のみを上書きできます。
  </Step>
  <Step>
    ### インストール

    リリースを開始し、コマンド結果を待ちます。継続的な Helm 進捗ストリームはありません。
  </Step>
</Steps>

## アップグレードとロールバック

<Steps>
  <Step>
    ### リリースを開く

    リリース詳細ビューを開き、現在のリビジョンと履歴を確認します。
  </Step>
  <Step>
    ### アップグレード

    values と利用できるチャート参照を編集してアップグレードします。独立した新バージョン選択は保証しません。
  </Step>
  <Step>
    ### ロールバック

    履歴から以前のリビジョンを選択し、ロールバックします。
  </Step>
</Steps>

## リリースをアンインストール

クラスターで不要になったリリースは削除してください。

<Callout type="warn">
  アンインストールはHelmが作成したKubernetesリソースを削除しますが、チャートがインストールしたPersistentVolumeClaimやCRDは常に削除されるとは限りません。本番環境のリリースを削除する前に、チャートのドキュメントで`--keep-history`や`keepCRDs`の動作を確認してください。
</Callout>
