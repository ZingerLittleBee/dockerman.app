Dockermanを離れることなく、Helmを使用してチャートリポジトリとリリースを管理します。

Dockermanは初回使用時にHelmバイナリを自動的にダウンロードおよび管理し、SHA-256チェックサム検証を行います。Helmを別途インストールする必要はありません。

## リポジトリ

よく使用するリポジトリを追加し、最新のチャートインデックスが必要なときに更新してください。

<Steps>
  <Step>
    ### リポジトリを追加

    リポジトリ名とURLを入力します。例えばBitnami、Jetstack、ingress-nginxなどです。
  </Step>
  <Step>
    ### リポジトリを更新

    リポジトリを追加または変更した後、チャートインデックスを更新します。
  </Step>
  <Step>
    ### リポジトリを削除

    Dockermanで不要になったリポジトリは削除してください。
  </Step>
</Steps>

## チャートを参照

追加 repository の index を検索して chart を選びます。embedded README や完全な version browser は保証しません。

## リリースをインストール

<Steps>
  <Step>
    ### チャートとバージョンを選択

    repository result が提供する chart を選び、install 前に effective version を確認します。
  </Step>
  <Step>
    ### リリース名とネームスペースを設定

    インストール前にリリース名と対象ネームスペースを設定します。
  </Step>
  <Step>
    ### values.yamlを編集

    Dockermanはチャートのデフォルト値をMonacoに読み込み、必要な値のみを上書きできます。
  </Step>
  <Step>
    ### インストール

    release を開始して command result を待ちます。continuous Helm progress stream はありません。
  </Step>
</Steps>

## アップグレードとロールバック

<Steps>
  <Step>
    ### リリースを開く

    リリース詳細ビューを開き、現在のリビジョンと履歴を確認します。
  </Step>
  <Step>
    ### アップグレード

    values と利用可能な chart reference を編集して upgrade します。独立した new-version picker は保証しません。
  </Step>
  <Step>
    ### ロールバック

    履歴から以前のリビジョンを選択し、ロールバックします。
  </Step>
</Steps>

## リリースをアンインストール

クラスターで不要になったリリースは削除してください。

<Callout type="warn">
  アンインストールはHelmが作成したKubernetesリソースを削除しますが、チャートがインストールしたPersistentVolumeClaimやCRDは常に削除されるとは限りません。本番環境のリリースを削除する前に、チャートのドキュメントで`--keep-history`や`keepCRDs`の動作を確認してください。
</Callout>
