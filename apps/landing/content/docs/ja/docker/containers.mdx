Containers page で、選択中の runtime 上の container を検索、確認、管理します。

## Lifecycle

利用できる action は container state と runtime に依存します。対応している場合、start、stop、restart、pause、unpause、rename、remove、inspect、logs、terminal、stats、clone、commit、backup、restore が表示されます。

<Callout type="info">
  Pause は runtime の pause API を使い、`SIGSTOP` を送るという契約ではありません。UI に force option がある場合は running container も remove できます。
</Callout>

## Create

create dialog は選択した local image と option から設定を作ります。missing image の自動 pull や、作成後の自動 start は保証しません。必要なら先に pull し、作成後に明示的に start してください。

ports、mounts、environment、resource limits、restart policy、network を確認します。runtime capability によって unsupported option は非表示になります。

## Inspect、clone、commit

- **Inspect** は runtime が返す container data を表示します。
- **Clone** は対応する設定を create flow にコピーしますが、volume data はコピーしません。
- **Commit** は writable layer を image に保存し、mounted volume data は含みません。

## Backup と restore

backup archive には manifest と、選択した container、volume、bind mount data が入ります。restore 前に preview し、任意の host path は自動的に「safe」と判定されないため各 bind mount を確認してください。

restore は対応する resource を再作成しますが、元の network の存在や container の自動 start は保証しません。name、ports、volumes、networks、image を確認してから必要に応じて start します。

<Callout type="warn">
  archive には filesystem data、environment value、bind mount content が含まれる可能性があります。
</Callout>

## Batch action

page の batch mode を有効にして複数 row を選びます。現在の toolbar に出る action だけが対象で、通常の Ctrl/Cmd+Click や single-letter shortcut は契約ではありません。
