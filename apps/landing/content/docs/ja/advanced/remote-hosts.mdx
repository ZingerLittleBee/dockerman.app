---
title: "リモートホスト (SSH)"
description: "SSH トンネル経由でリモート Docker ホストを管理し、ホストセレクターから切り替え。"
---

Dockerman は SSH でリモート Docker デーモンの Unix ソケットを転送します。基本的な Docker 操作、ログ、ターミナルは利用できますが、ランタイムやホストに依存する機能が localhost と同一とは限りません。たとえば Podman ターゲットでは Compose を利用できません。

## リモートホストの追加

ホストを一度追加すると、他のDockerターゲットと同様に切り替えることができます。

<Steps>
  <Step>
    ### Hostsを開く

    Hosts ビューまたはメインウィンドウの Host Switcher から開きます。
  </Step>
  <Step>
    ### Add Hostをクリック

    **Add Host**をクリックします。接続詳細を入力するダイアログが表示されます。
  </Step>
  <Step>
    ### SSH詳細を入力

    ホスト、ポート（デフォルト`22`）、ユーザー、認証方法を入力します。
  </Step>
  <Step>
    ### ランタイム設定を選択

    **Auto**、**Docker**、または**Podman**を選択します。Podmanの場合、Dockermanはrootless（`/run/user/<uid>/podman/podman.sock`）およびrootful（`/run/podman/podman.sock`）ソケットを自動検出します。
  </Step>
  <Step>
    ### テストして保存

    接続をテストしてから保存します。Dockermanはテストトンネルを開き、ランタイムを検出して検出されたランタイムタイプを表示します。
  </Step>
</Steps>

## キーベース認証とパスワード認証

リモートホストの設定に合わせたSSH認証方法を選択してください。

<Tabs items={['SSH key', 'Password']}>
  <Tab>
    秘密鍵を貼り付けるか、キーファイルを選択します。ファイルを選ぶと、Dockerman はパスだけでなく鍵の内容を読み取って保存します。

    <Callout type="warn">
      現在のデスクトップアプリは、秘密鍵の内容を可逆な Base64 形式でローカルデータベースに保存します。Base64 は暗号化ではありません。ローカルアカウントとアプリデータを保護してください。
    </Callout>
  </Tab>
  <Tab>
    パスワードも可逆な Base64 形式でローカルデータベースに保存されます。信頼できる端末とユーザーアカウントでのみ使用してください。
  </Tab>
</Tabs>

## ホスト間の切り替え

トップバーのHost Switcherを使用して、`localhost`と設定済みの各リモートホスト間を移動できます。ホストを切り替えると、新しく選択されたターゲットのすべてのデータが再読み込みされます。

## 自動再接続

Dockerman は SSH トンネルを監視し、3、5、10 秒後に再試行します。すべて失敗すると接続失敗ダイアログを開きます。

## SSHトンネルの仕組み

Dockerman は SSH セッションを開き、ローカル Unix ソケットをリモートランタイムのソケットへ転送します。そのホストへの Docker API 通信はトンネルを通りますが、レジストリ、更新、分析などのアプリ通信は別接続であり、SSH を経由しません。

## セキュリティに関する注意事項

<Callout type="warn">
  信頼できるネットワーク上の信頼できるリモートホストのみを設定してください。SSH認証情報はローカルマシンに保存されるため、それらを保存するシステムは機密情報として扱ってください。
</Callout>
