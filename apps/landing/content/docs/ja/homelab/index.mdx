title: Homelab

---

Homelab 機能でセルフホストサービスを監視し、問題が起きたときに通知を受け取り、ツールを行き来せずに直せます。

## Homelabモードの理由

ほとんどのコンテナ管理はデスクの前で行います。Homelab モードはそれ以外をカバーします。離席中、深夜 3 時にサービスが落ちたとき、見ていない間に新しいイメージが出たときです。

Dockerman は **デスクトップ優先、ローカル優先** です。管理用コンテナをデプロイしたり、管理用ポートを公開したりしません。レジストリ、リモートホスト、通知の機密データはアプリのローカルデータに保存され、システム Keychain の利用は保証されません。そのディレクトリを保護してください。

## エンドツーエンドのワークフロー

<Steps>
  <Step>
    ### 通知チャンネルの設定

    [Telegram、ntfy、Gotify、Discord、または汎用 webhook](/ja/docs/homelab/notifications) を接続し、離席中でも Dockerman が連絡できるようにします。
  </Step>
  <Step>
    ### プリセットのアラートルールを有効化

    *Restart loop* と *Container crash (non-zero exit)* は設定済みですが無効です。カスタムルールの作成は Coming Soon です。
  </Step>
  <Step>
    ### イメージ更新の購読

    重要なサービスの[イメージアップグレード監視](/ja/docs/homelab/image-watches)を有効にします。Dockerman はバックグラウンドでレジストリを確認し、新しいバージョンが出たら通知します。
  </Step>
  <Step>
    ### 診断と修正

    問題が起きたときは、ワンクリックで[診断バンドル](/ja/docs/homelab/diagnostic-bundle)を作り、[組み込みエディタ](/ja/docs/docker/compose#composeyamlの編集)または[.env エディタ](/ja/docs/docker/containers#ビジュアル-env-エディタ)で Compose YAML を編集して、修正を適用します。
  </Step>
</Steps>

## 実行を維持する方法

Dockerman は **トレイ常駐** です。メインウィンドウを閉じるとシステムトレイへ移り、バックグラウンドタスクは動き続けます。トレイアイコンから終了すると、バックグラウンドタスクが止まることを知らせます。

完全なシステムサービス（launchd / systemd / Windows Service）は将来のリリースで予定されています。
