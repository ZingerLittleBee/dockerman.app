Agent Sandbox では、ゲストコードが実行された瞬間から microVM 内のすべて（Guest Agent を含む）を信頼できない領域として扱います。ホストへの書き戻し検証、ネットワーク遮断、シークレット置換はすべてホスト側で強制されます。

## サンドボックスワークスペース（既定は copy-in）

ホストのプロジェクトディレクトリを接続する場合、Dockerman は既定で **copy-in** モード（`--mount-mode copy-in`）を使用します。

- **安全なコピー時フィルタリング**：`.gitignore` を尊重し、既定で `.env*` や秘密鍵ファイルを除外するとともに、**`.git/` ディレクトリを完全に除外**してフックや設定・認証情報がゲストへ入るのを防ぎます。
- **シンボリックリンク逸脱の防止**：ワークスペース外を指すシンボリックリンクは一切辿らずスキップします。ワークスペース内に収まる相対リンク（`CLAUDE.md -> AGENTS.md` など）は保持されます。
- **ホスト側 SHA-256 マニフェスト**：コピー時に全対象パスの SHA-256 ベースラインをホスト側で記録します。`sandbox diff` と **ホストへ適用** はゲスト側メタデータを信用せず、このマニフェストと照合検証します。

### ホストへ適用（Apply to Host）の必須ガード

ホストディレクトリへ変更を書き戻す際、Dockerman は以下を強制します。

1. **`.git` 書き込み拒否**：Unicode 正規化・ASCII 大文字小文字正規化・HFS+/NTFS 短縮名正規化後に `.git` コンポーネントを含むあらゆるパスを拒否します（CVE-2014-9390 対策、サブモジュール・ネストリポジトリ含む）。
2. **シンボリックリンク逸脱ブロック**：ホスト側のシンボリックリンクを辿らずコンポーネント単位で開閉（`O_NOFOLLOW`）し、既存リンク経由のディレクトリ外書き込みを遮断します。
3. **ホスト競合検知**：コピー後にホスト側で編集されたファイルはベースラインハッシュ不一致として競合エラーで中断し、意図しない上書きを防ぎます。
4. **明示的な承認境界**：書き戻しにはデスクトップ GUI 確認ダイアログまたは対話型 CLI TTY での承認が必要です（`--yes` はホスト側自動化スクリプト専用）。

<Callout type="warn">
  macOS Apple Silicon では `--mount-mode direct` によるダイレクトマウントも明示的に選択できますが、copy-in の Diff/Apply 検証をバイパスし隔離境界が弱まります。Linux Firecracker ホストでは利用できません。
</Callout>

## ゼロ NIC 外向きポリシー

サンドボックスには**仮想ネットワークインターフェースが存在しません**（macOS では `libkrun` TSI を無効化、Linux Firecracker では `virtio-net` TAP なし）。ゲスト内の TCP / DNS 通信は内部 `TUN` デバイスで透過的に捕捉され、`virtio-vsock` 経由でホスト側のユーザー空間プロキシへ転送されるため、`HTTP_PROXY` を無視するツールでも強制されます。

| ポリシー | 動作 |
| --- | --- |
| `public-only` *（既定）* | パブリックインターネットへの TCP / DNS を許可しつつ、IPv4/IPv6 ループバック（`127.0.0.0/8`, `::1`）、RFC1918 プライベート LAN（`10/8`, `172.16/12`, `192.168/16`）、リンクローカル・クラウドメタデータ（`169.254.0.0/16`, `fe80::/10`）、CGNAT / Tailscale（`100.64.0.0/10`）、ULA（`fc00::/7`）、IPv4 射影 IPv6 アドレスをすべて遮断します。 |
| `allowlist` | `--egress-allowlist` に明示したドメインのみ TCP / DNS を許可します（プライベート IP 遮断は引き続き有効）。 |
| `offline` | すべての外向き TCP / DNS 通信を遮断します。 |

- **DNS リバインディング対策**：ホスト側プロキシがゲストの DNS 問い合わせを解決し、返却されたすべての IP が拒否レンジ外であることを検証したうえで、検証済み IP へ直接接続します。
- **対象プロトコル**：TCP と DNS のみ。DNS 以外の UDP と ICMP は既定でドロップされます。
- **監査ログ**：許可・遮断された全イベントは **ネットワーク** タブでリアルタイムに確認できます。

<Callout type="info">
  `public-only` はホスト端末・ローカルサービス・社内 LAN を保護するものであり、信頼できないコードがワークスペースの内容をパブリックサーバーへ送信すること自体は防ぎません。機密リポジトリでは `offline` または厳格な `allowlist` を使用してください。
</Callout>

## ドメイン限定シークレット注入プロキシ

API キーの実値を microVM へ直接渡す代わりに、`--secret` で特定ドメインに限定したプレースホルダー環境変数を注入できます。

```bash
dockerman sandbox create python:3.12-slim \
  --egress allowlist \
  --egress-allowlist api.openai.com \
  --secret OPENAI_API_KEY=env:OPENAI_API_KEY@api.openai.com
```

- microVM 内の `OPENAI_API_KEY` にはホスト生成のプレースホルダートークンのみが入ります。
- 許可ドメイン（`api.openai.com`）への送信時にホスト側プロキシが実値へ動的置換し、レスポンスに実値がエコーされた場合はゲストへ届く前にストリーム上で除去します。
- 実値は microVM のファイルシステム・環境変数・デスクトップ GUI には一切入りません。
