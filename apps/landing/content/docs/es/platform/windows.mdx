Windows tiene dos rutas de Docker compatibles: Docker Desktop o el Docker Engine WSL2 integrado.

## Comparación rápida

| Aspecto | Docker Desktop | Docker Engine WSL2 |
| --- | --- | --- |
| Suscripción | Requerida para la mayoría de empresas | No requerida |
| Huella de instalación | Instalación más grande | Distro WSL pequeña basada en Alpine |
| Uso de recursos | Mayor, porque ejecuta una VM y servicios | Menor, porque se ejecuta dentro de WSL2 |
| Esfuerzo de configuración | Instalador estándar | Automatizado por Dockerman |
| Soporte | Totalmente compatible | Totalmente compatible, añadido en la v4.3.0 |

## Opción A: Docker Desktop

<Steps>
  <Step>
    ### Instala Docker Desktop

    Descarga Docker Desktop desde docker.com y ejecuta el instalador.
  </Step>
  <Step>
    ### Asegúrate de que Docker Desktop esté en ejecución

    Espera a que el icono de la ballena indique que Docker Desktop está en ejecución.
  </Step>
  <Step>
    ### Inicia Dockerman

    Dockerman detecta Docker Desktop y se conecta a él.
  </Step>
</Steps>

## Opción B: Docker Engine WSL2

Añadido en la v4.3.0.

Dockerman incluye la ruta WSL2, así que no necesitas Docker Desktop ni configurar WSL a mano.

### Requisitos previos

- Windows 10 versión 2004 o posterior, o Windows 11.
- WSL2 instalado con `wsl --install` desde una sesión de PowerShell elevada.
- Virtualización habilitada en BIOS o UEFI.

### Asistente de configuración

El Asistente de configuración se ejecuta en el primer inicio cuando no se detecta Docker Desktop.

<Steps>
  <Step>
    ### Elige el Docker Engine WSL2

    Selecciona la ruta del Docker Engine WSL2 integrado cuando aparezca el diálogo de bienvenida.
  </Step>
  <Step>
    ### Importa Alpine

    Dockerman importa una distro WSL Alpine mínima para el Docker Engine.
  </Step>
  <Step>
    ### Instala Docker dentro de Alpine

    Dockerman instala Docker y configura el daemon para que inicie al iniciar sesión.
  </Step>
  <Step>
    ### Verifica la conexión

    Dockerman ejecuta una comprobación de salud y se conecta al nuevo daemon.
  </Step>
</Steps>

<Callout type="warn">
  No cierres Dockerman mientras el asistente está en ejecución. La primera configuración tarda unos minutos y debe terminar antes de que la aplicación sea usable.
</Callout>


### Qué hace el asistente

El asistente crea los archivos de la distro Alpine que Dockerman usa para ejecutar Docker.

<Files>
  <Folder name="(Alpine WSL2 distro)" defaultOpen>
    <File name="/etc/docker/daemon.json" />
    <Folder name="/etc/init.d">
      <File name="docker" />
    </Folder>
    <Folder name="/var/lib/docker">
      <File name="(Docker data root)" />
    </Folder>
  </Folder>
</Files>

### Edita daemon.json

Usa Configuración → Panel de configuración del daemon para editar `/etc/docker/daemon.json` en una vista de formulario para campos habituales o una vista JSON en crudo para el resto. Guardar reinicia Docker dentro de la distro Alpine.

### Recuperación tras fallo del daemon

Si el daemon de Docker falla, Dockerman muestra un banner con un botón de Reinicio y transmite los logs del fallo para diagnosticar.

### Reinstala la distro WSL2

Añadido en v5.3.0. Si la distro Alpine queda en un estado defectuoso, abre el asistente de configuración de WSL y haz clic en **Reinstall** para anular el registro de `dockerman-backend` e importar una imagen Alpine nueva.

<Callout type="warn">
  La reinstalación elimina toda la distribución WSL, incluidas las imágenes, los contenedores y los volúmenes de Docker, además de cualquier otro dato guardado en ella. Exporta o crea una copia de seguridad antes de continuar. Dockerman no conserva los volúmenes durante esta operación.
</Callout>

### Cambia la fuente del motor

Añadido en v5.3.0. La página WSL en Windows muestra un selector de **Fuente del motor** con dos tarjetas: el socket Docker nativo del sistema (Docker Desktop o cualquier Docker instalado en el sistema) y el Docker Engine WSL2 incluido en Dockerman. Elige una tarjeta y Dockerman reconecta el host local a esa fuente, sin toast ni guardado manual. El tipo de conexión Docker anterior (`socket`, `tcp`, `npipe`) se recuerda, así que volver a Docker nativo del sistema restaura tu configuración previa.

Si prefieres el flujo anterior, también puedes cambiar el tipo de conexión desde **Configuración → Configuración de Docker** y reconectar a mano.

## Supervisión de recursos para WSL2

Usa [Stats](/es/docs/docker/stats) para vigilar el Engine WSL2 como cualquier otro daemon de Docker. Si Windows parece consumir mucha memoria, comprueba el ballooning de la VM WSL2 en el Administrador de tareas.

## Solución de problemas

<Accordions>
  <Accordion title="WSL2 no instalado">
    Instala WSL2 con `wsl --install`, reinicia si Windows lo pide y verifica la instalación con `wsl --status`.
  </Accordion>
  <Accordion title="Virtualización deshabilitada">
    Habilita la virtualización en BIOS o UEFI y confirma que está activa desde el Administrador de tareas → Rendimiento → CPU.
  </Accordion>
  <Accordion title="Fallo al importar Alpine">
    Comprueba el espacio libre en disco, cierra cualquier proceso WSL o Docker obsoleto y revisa el Log de la aplicación para ver el error exacto de importación.
  </Accordion>
  <Accordion title="El daemon no inicia tras reiniciar">
    Ve a [Recuperación tras fallo del daemon](/es/docs/platform/windows#recuperación-tras-fallo-del-daemon) y [Edita daemon.json](/es/docs/platform/windows#edita-daemonjson). Ambas secciones cubren los fallos de inicio habituales.
  </Accordion>
</Accordions>
