title: Skills de Claude
description: Instala el plugin oficial de Claude Code de Dockerman para operar la CLI dockerman desde un asistente de IA.
---

Si usas [Claude Code](https://docs.claude.com/en/docs/claude-code/overview), Dockerman publica un **plugin** oficial con un skill que enseña al asistente a usar la CLI `dockerman`: mapa de comandos, formas de salida, reglas de streaming, particularidades del ámbito de k8s y reglas de seguridad para acciones destructivas. Instálalo una vez y Claude usará `dockerman` cuando el usuario pregunte por Docker, Compose o Kubernetes, aunque no diga «use dockerman».

## Instalación rápida

Dentro de Claude Code:

```text
/plugin marketplace add mandocker/skills
/plugin install dockerman
```

Esto registra el marketplace en [github.com/mandocker/skills](https://github.com/mandocker/skills) e instala el plugin `dockerman` en tu ámbito de usuario. Claude Code carga el skill en la siguiente sesión: sin reinicio ni cambios de configuración. El skill queda con el namespace `dockerman:dockerman-cli`.

Para verificar:

```text
/plugin list
```

Deberías ver `dockerman` habilitado. Antes de automatizar, comprueba `dockerman --help` y la salida real; el plugin puede ir por detrás de la app.

## Qué obtienes

El plugin contiene un único skill, `dockerman-cli`, que cubre:

- Una descripción de SKILL pensada para dispararse en prompts de Docker / Compose / Kubernetes / kubectl aunque el usuario no diga «dockerman».
- El mapa de comandos (`container`, `image`, `compose`, `network`, `volume`, `host`, `system`, `hub`, `k8s`, `tunnel`, `trivy`, `wsl`, `events`, `schema`, `call`).
- Notas sobre la forma de la salida: por ejemplo, `dockerman k8s pod list` devuelve `{ forbidden, items, truncated }` con campos **aplanados** (`.name`, `.namespace`, `.restarts`, `.status`), no el árbol `metadata.*` de kubectl.
- Las dos reglas de ámbito de k8s que más se tropiezan al principio: `--cluster` es obligatorio si no hay cluster seleccionado, y `pod list` sin `--namespace` solo devuelve el namespace `default` (omite en silencio `kube-system`).
- Advertencias para operaciones destructivas como `container restore -y`. Un backup no siempre exige `-y`.
- Un cookbook de `jq` (`references/output-parsing.md`) para proyectar la salida JSON sin llenar el contexto.

## Actualizar o desinstalar

```text
/plugin update dockerman
/plugin uninstall dockerman
```

Las actualizaciones traen la última `version` del `plugin.json` del marketplace. El plugin vive en `~/.claude/plugins/`; desinstalarlo lo elimina.

## Fijar una revisión concreta

Añade `@<git-ref>` (rama, tag o SHA) a la URL del marketplace:

```text
/plugin marketplace add mandocker/skills@v1.0.0
/plugin install dockerman
```

Útil cuando quieres una configuración reproducible para un equipo: todos quedan en la misma revisión hasta que muevas el pin del marketplace.

## Configuración para equipos

Para autoinstalarlo a todos los miembros de un proyecto, añade el marketplace al `.claude/settings.json` en la raíz del repo:

```json
{
  "extraKnownMarketplaces": {
    "dockerman": {
      "source": {
        "source": "github",
        "repo": "mandocker/skills"
      }
    }
  }
}
```

Los compañeros solo tienen que ejecutar `/plugin install dockerman`; no hace falta que añadan el marketplace ellos.

## Otros agentes

Los archivos del skill están en [github.com/mandocker/skills/tree/main/skills/dockerman-cli](https://github.com/mandocker/skills/tree/main/skills/dockerman-cli). Cualquier agent harness que lea skills al estilo Claude (Cursor, Anthropic Agent SDK, etc.) puede clonar el repo y apuntar a ese directorio.
