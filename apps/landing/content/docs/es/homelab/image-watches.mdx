---
title: Seguimiento de actualizaciones de imágenes
description: Consulta registros de imágenes en segundo plano y recibe un aviso cuando hay una versión nueva.
---

El seguimiento de actualizaciones hace que Dockerman consulte registros en segundo plano y envíe un aviso cuando hay una versión nueva. Por defecto **solo notifica y nunca dispara una actualización automática**; tú decides cuándo aplicar el cambio.

## Cómo funciona

1. Te suscribes a las imágenes que te importan (por host, por referencia de imagen).
2. El [programador en segundo plano](/es/docs/homelab/scheduler) ejecuta la tarea `image_upgrade_check` en un intervalo configurable (por defecto: cada 6 horas).
3. Para cada imagen suscrita, Dockerman resuelve una credencial de registro con el **resolutor de credenciales** y compara el digest local con el del registro remoto. Si las credenciales son ambiguas, **la comprobación falla** en lugar de adivinar.
4. Cuando hay digests nuevos, Dockerman envía una sola notificación agrupada por tus [canales de notificación](/es/docs/homelab/notifications) configurados y escribe un cursor de historial para que la siguiente ejecución continúe donde esta lo dejó.

## Suscribirse a una imagen

<Tabs items={['Desde un contenedor', 'Desde un stack Compose']}>
  <Tab>
    Abre el menú de acciones del contenedor (el mismo que tiene **Verificar actualización** y **Actualizar**) y haz clic en **Monitorear actualizaciones**.

    La suscripción está ligada al host y a la referencia de imagen, así que sobrevive a reconstrucciones del contenedor.
  </Tab>
  <Tab>
    Abre el menú overflow del stack Compose y haz clic en **Monitorear todas las imágenes para actualizaciones**. Esto suscribe todas las imágenes del stack de una vez.

    Para dar de baja imágenes sueltas más tarde, usa la página dedicada de seguimientos.
  </Tab>
</Tabs>

## La página de seguimiento de actualizaciones

La página dedicada muestra todas las suscripciones juntas.

**Barra superior:**
- **Intervalo de verificación** — cada cuánto corre el programador (se escribe en la tarea del programador; no hay otro ajuste paralelo)
- **Canales por defecto** — elige qué [canales de notificación](/es/docs/homelab/notifications) reciben avisos de actualización
- **Verificar todas ahora** — lanza una comprobación inmediata de todas las suscripciones

**Tabla principal:**

| Columna | Descripción |
| --- | --- |
| Imagen | La referencia de imagen (p. ej. `jellyfin/jellyfin:latest`) |
| Contenedores | Qué contenedores usan esta imagen en este host |
| Estado | Estado actual de la comprobación (ver abajo) |
| Última verificación | Cuándo se ejecutó la última comprobación y qué encontró |
| Acciones | Eliminar suscripción, lanzar comprobación manual |

La tabla muestra última comprobación, última notificación, digest remoto, estado, reintento, host y contenedores. No hay un panel por fila con todo el historial.

## Estados

| Estado | Significado |
| --- | --- |
| `unknown` | Aún no se ha ejecutado ninguna comprobación |
| `up_to_date` | Los digests local y remoto coinciden |
| `upgrade_available` | Hay un digest más nuevo en el registro |
| `watchtower_managed` | Todos los contenedores con esta imagen tienen la etiqueta `enable=true` de Watchtower, así que Dockerman cede a Watchtower |
| `orphaned` | Ningún contenedor en ejecución usa esta imagen en este host (p. ej. se eliminó el stack) |
| `error` | La comprobación falló (registro inalcanzable, error de autenticación, límite de tasa, etc.) |

## Mensajes de notificación

Cuando una misma ejecución encuentra una o más actualizaciones, Dockerman envía un solo mensaje agregado:

```
Título: 3 actualizaciones de imagen disponibles en prod-nas

Cuerpo:
- jellyfin/jellyfin:latest -> a3f2e1 (1 contenedor: jellyfin)
- redis:7-alpine -> 8c91b4 (2 contenedores: cache, sessions)
- grafana/grafana:latest -> 5e44aa (1 contenedor: grafana)

Abrir Dockerman: dockerman://
```

El enlace profundo abre la ventana principal de Dockerman.

### Cooldown de notificaciones

Las notificaciones van por digest: Dockerman recuerda el último digest del que te avisó. Solo envía otro aviso cuando el digest remoto vuelve a cambiar. Cuando todos tus contenedores alcanzan el digest notificado, el cooldown se reinicia para que la siguiente actualización del registro dispare un aviso nuevo.

## Coexistencia con Watchtower

Si ya ejecutas Watchtower, Dockerman detecta la etiqueta `com.centurylinklabs.watchtower.enable=true` en los contenedores y actúa así:

- **Todos los contenedores etiquetados:** la suscripción muestra estado `watchtower_managed` y no avisa.
- **Mixto (algunos etiquetados, otros no):** Dockerman ignora los contenedores gestionados por Watchtower y solo avisa del resto.
- **Sin etiquetas:** Dockerman trata todos los contenedores con normalidad.

<Callout type="info">
  Dockerman solo reconoce la etiqueta explícita `enable=true`. Si Watchtower corre en modo por defecto (vigila todo sin etiquetas), Dockerman no lo detecta. En ese caso puedes recibir avisos duplicados de las dos herramientas.
</Callout>

## Límites de tasa del registro

Dentro de una misma ejecución, Dockerman deduplica por referencia de imagen: la misma imagen se consulta una vez, da igual cuántos contenedores la usen. Si un registro devuelve una cabecera `Retry-After`, Dockerman la respeta. Sin esa cabecera, aplica un backoff de 15 minutos. Las suscripciones en backoff muestran el estado `error` con una nota de cuándo será el siguiente reintento.

## Cancelar suscripción

Elimina una suscripción desde la página de seguimiento. A partir de ahí no hay más comprobaciones ni avisos para esa imagen en ese host.

## Consejos

- Empieza por las 3-5 imágenes que más te importan (p. ej. el servidor de medios, la base de datos, el proxy inverso).
- Deja el intervalo de 6 horas salvo que tengas un motivo concreto para sondear más a menudo. Intervalos más cortos aumentan el uso de la API del registro.
- Usa **Verificar todas ahora** tras añadir suscripciones para ver el estado sin esperar a la siguiente ejecución programada.
- El aviso te dice que existe una versión nueva. Para aplicarla, usa **Verificar actualización** y **Actualizar** en el menú del contenedor.
