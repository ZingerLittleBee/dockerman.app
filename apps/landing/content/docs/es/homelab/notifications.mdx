title: Notificaciones

Dockerman puede enviar notificaciones por varios canales para enterarte de lo que ocurre cuando no estás en el escritorio. Los canales usan un **esquema de URL compatible con Shoutrrr**, el mismo formato que Watchtower, Beszel y otras herramientas de homelab.

## Canales soportados

| Canal | Formato de URL | Notas |
| --- | --- | --- |
| Telegram | `telegram://token@telegram?chats=chat_id` | Token de bot de BotFather |
| ntfy | `ntfy://ntfy.sh/topic` o `ntfy://user:pass@ntfy.sh/topic` | Autoalojado o ntfy.sh |
| Gotify | `gotify://gotify.example.com/token` | Servidor Gotify autoalojado |
| Discord | `discord://token@id` | URL de webhook convertida a formato Shoutrrr |
| Webhook | `generic://example.com/webhook` | POST JSON genérico a cualquier endpoint |
| Notificación del sistema | Integrado, no se necesita URL | Notificaciones nativas de macOS, Windows y Linux |

Las notificaciones del sistema siempre están disponibles y habilitadas por defecto. No cuentan como un canal «externo».

## Compatibilidad actual del escritorio

La página de Notificaciones puede listar canales configurados y enviar una prueba. La interfaz de escritorio actual no ofrece un flujo completo para añadir, editar, deshabilitar o eliminar canales. Los adaptadores internos no sustituyen esa interfaz ausente.

## Seguridad de credenciales

El daemon actual guarda los secretos completos en `secrets/notification-channels.json`, dentro de los datos de Dockerman. En Unix restringe el archivo al usuario actual, pero los valores no se almacenan en el llavero del sistema.

<Callout type="warn">
  Trata el directorio de datos de Dockerman como información sensible. Las URL de webhook genéricas pueden incluir credenciales en la ruta o la consulta; revisa logs y diagnósticos antes de compartirlos.
</Callout>

## Consejos

- Si ya usas URLs de Shoutrrr con Watchtower o Beszel, puedes pegar la misma URL en Dockerman.
- Para Discord, convierte tu URL de webhook (`https://discord.com/api/webhooks/ID/TOKEN`) al formato Shoutrrr: `discord://TOKEN@ID`.
- El canal de webhook genérico envía un POST JSON con campos `title` y `body`. Sirve para cualquier servicio que acepte webhooks.
