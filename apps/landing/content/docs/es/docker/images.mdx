Descarga, construye, sube, analiza y escanea imágenes desde aquí, y explora Docker Hub en la propia aplicación.

## La lista de imágenes

Ordena por tamaño o fecha de creación y cambia entre todas las imágenes y las huérfanas cuando quieras limpiar capas antiguas.

<Tabs items={['Todas', 'Huérfanas']}>
  <Tab>
    Todas las imágenes incluyen cada etiqueta disponible en local. Usa esta vista para inspeccionar, reetiquetar, construir, subir o escanear.
  </Tab>
  <Tab>
    Las imágenes huérfanas son capas sin etiquetar que dejan las construcciones. Usa esta vista para eliminar intermediarios que ya no sirvan.
  </Tab>
</Tabs>

## Descargar una imagen

Dockerman sugiere registros, nombres de imagen y etiquetas mientras escribes en el cuadro de descarga. Añadido en la v4.7.0.

<Steps>
  <Step>
    ### Abrir el diálogo de descarga

    Haz clic en Pull en la página de Imágenes.
  </Step>
  <Step>
    ### Introducir la referencia de la imagen

    Escribe el registro, repositorio y etiqueta que quieres descargar.
  </Step>
  <Step>
    ### Ver el progreso en streaming

    Sigue la descarga y extracción de capas hasta que la imagen aparezca en la lista.
  </Step>
</Steps>

## Explorar Docker Hub

Añadido en la v4.6.0.

El navegador de Hub integrado sirve para buscar, inspeccionar y descargar imágenes públicas sin pasar por la interfaz web.

<Steps>
  <Step>
    ### Abrir el navegador de Hub

    Desde la página de Imágenes, haz clic en Explorar Docker Hub.
  </Step>
  <Step>
    ### Buscar una imagen

    Escribe una consulta y revisa las insignias de oficial y verificado en los resultados.
  </Step>
  <Step>
    ### Leer el README y las etiquetas

    Haz clic en una imagen para ver su README en línea y la lista completa de etiquetas.
  </Step>
  <Step>
    ### Descargar una etiqueta concreta

    Haz clic en Pull junto a la etiqueta que quieres usar.
  </Step>
</Steps>


## Construir desde un Dockerfile

La construcción usa el mismo daemon de Docker que el resto de Dockerman. BuildKit se activa solo si el daemon lo soporta.

<Steps>
  <Step>
    ### Elegir un contexto de construcción

    Selecciona una carpeta local que contenga el Dockerfile.
  </Step>
  <Step>
    ### Revisar o editar el Dockerfile

    Ábrelo en Monaco y guarda los cambios en disco antes de construir.
  </Step>
  <Step>
    ### Establecer el nombre de la imagen y los argumentos de construcción

    Fija la etiqueta de la imagen, los argumentos de construcción opcionales y una etapa objetivo si la necesitas.
  </Step>
  <Step>
    ### Ejecutar la construcción

    Los registros de construcción se muestran en la terminal hasta que la imagen aparece en la lista de Imágenes.
  </Step>
</Steps>

<Callout type="info">
  Dockerman respeta `.dockerignore` en el contexto de construcción seleccionado.
</Callout>

## Subir a un registro

Añadido en la v4.6.0.

Sube una imagen etiquetada tras elegir un registro configurado en el gestor de registros de Dockerman.

<Steps>
  <Step>
    ### Etiquetar la imagen para el registro de destino

    Usa un nombre completo como `registry.example.com/team/app:1.2.0`.
  </Step>
  <Step>
    ### Configurar las credenciales del registro

    Añade o elige una entrada del gestor. El diálogo toma las credenciales de esa entrada; no promete importar `~/.docker/config.json` ni aceptar credenciales ad hoc por cada subida.
  </Step>
  <Step>
    ### Subir con progreso en streaming

    Sigue el progreso de subida hasta que el registro acepte la nueva etiqueta.
  </Step>
</Steps>

<Callout type="info">
  Funcionan registros públicos y privados, entre ellos Docker Hub, GHCR, Harbor, AWS ECR, Nexus y GitLab Container Registry.
</Callout>

## Analizar el tamaño de la imagen

Abre la vista de Tamaño de Imagen para ver el árbol de capas y dónde ocupa espacio la imagen.

- Busca cachés de paquetes grandes que se quedaron en la capa final.
- Busca artefactos de construcción que deberían haberse copiado a una imagen de runtime más pequeña.
- Busca capas `COPY` redundantes que dupliquen los mismos archivos.

## Operaciones de etiquetado

Etiqueta, quita etiquetas o reetiqueta una imagen para otro repositorio o registro. Reetiquetar cambia solo la referencia; las capas se quedan donde están.

## Escanear con Trivy

Añadido en la v4.6.0.

Escanea una imagen para encontrar vulnerabilidades conocidas en las capas instaladas.

### Instalación por primera vez

Si falta el binario gestionado, Dockerman pide instalarlo. Trivy aún puede descargar o actualizar su base de datos durante el escaneo.

<Callout type="warn">
  La instalación y las actualizaciones de la base de datos pueden requerir red. El tamaño y la caché dependen de la versión instalada.
</Callout>

### Ejecutar un escaneo

<Steps>
  <Step>
    ### Seleccionar una imagen

    Elige la imagen que quieres escanear desde la página de Imágenes.
  </Step>
  <Step>
    ### Hacer clic en Escanear con Trivy

    Dockerman inicia el escaneo y transmite el progreso a la vista de informes.
  </Step>
  <Step>
    ### Esperar el informe

    Un escaneo típico tarda de 30 segundos a 3 minutos, según el tamaño de la imagen.
  </Step>
</Steps>

### Leer el informe

Dockerman agrupa los hallazgos por severidad. Puedes expandir cada uno para ver el ID de CVE, la descripción, las versiones afectadas y las versiones de corrección, si constan. Exporta el informe original como JSON para pasarlo a CI o archivarlo.


## Limpieza

- Elimina imágenes huérfanas desde la pestaña Huérfanas para limpiar restos de construcción.
- Borra versiones antiguas con selección múltiple cuando ya no necesites una etiqueta.
- Usa **Purgar** en la página de Imágenes para pedir al runtime que elimine imágenes no usadas.
