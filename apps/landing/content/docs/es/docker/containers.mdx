Usa la página Contenedores para buscar, inspeccionar y gestionar contenedores del runtime seleccionado.

## Ciclo de vida

Las acciones dependen del estado y del runtime. Cuando están soportadas aparecen iniciar, detener, reiniciar, pausar, reanudar, renombrar, eliminar, inspeccionar, logs, terminal, estadísticas, clonar, commit, backup y restore.

<Callout type="info">
  Pausar usa la API pause del runtime; no se documenta como `SIGSTOP`. Si la UI ofrece force, puede eliminar un contenedor en marcha sin detenerlo primero.
</Callout>

## Crear

El diálogo crea una configuración desde la imagen local y las opciones elegidas. Crear no promete descargar una imagen ausente ni iniciar el contenedor. Descarga primero cuando haga falta y arráncalo explícitamente después.

Revisa puertos, mounts, variables de entorno, límites, política de reinicio y red. La UI oculta opciones que el backend seleccionado no soporta.

## Inspeccionar, clonar y commit

- **Inspeccionar** muestra los datos devueltos por el runtime.
- **Clonar** copia la configuración soportada a un nuevo flujo, no los datos de volúmenes.
- **Commit** guarda la capa editable como imagen y no incluye datos montados.

## Backup y restore

El backup crea un archivo Dockerman con manifest y los datos seleccionados de contenedor, volúmenes y bind mounts. Previsualízalo antes de restaurar y revisa cada bind mount: Dockerman no clasifica rutas arbitrarias como seguras.

Restore recrea recursos soportados, pero no garantiza que existan las redes originales ni que el contenedor arranque automáticamente. Revisa nombre, puertos, volúmenes, redes e imagen y luego inícialo si corresponde.

<Callout type="warn">
  El archivo puede contener datos del sistema de archivos, valores de entorno y contenido de bind mounts. Trátalo como sensible.
</Callout>

## Acciones por lotes

Activa el modo batch de la página para seleccionar varias filas. Sólo están soportadas las acciones visibles en la barra actual; Ctrl/Cmd+Clic y los atajos de una letra no son un contrato.
