---
title: "Port Forward y DNS"
description: "Reenvía puertos de Pod, Service o Deployment y configura el DNS local de Dockerman."
---

Dockerman puede reenviar un puerto de un Pod, Service o Deployment a la máquina local. Los forwards activos pueden reconectarse según los ajustes de Kubernetes.

## Iniciar un forward

1. Abre un recurso compatible y selecciona **Port forward**.
2. Elige el puerto remoto y un puerto local libre.
3. Inicia el forward y usa la dirección local mostrada.
4. Deténlo desde la lista de forwards activos al terminar.

## DNS automático

Al iniciar un forward, Dockerman registra un nombre `<target>.<namespace>.<suffix>`. El suffix inicial es `k8s.local` y el listener UDP usa el puerto `5353`.

No existe un interruptor independiente y Dockerman no modifica `/etc/hosts`.

### Configuración del resolver

- macOS: configura `/etc/resolver/<suffix>` para apuntar al puerto DNS de Dockerman.
- Linux: configura systemd-resolved u otro resolver para enviar el suffix al DNS local.
- Windows: la integración automática con el resolver del sistema no está implementada.

Los cambios de suffix o puerto afectan a registros futuros. Las aplicaciones existentes pueden guardar respuestas DNS en caché.
