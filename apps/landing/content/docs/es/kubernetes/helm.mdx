Gestiona repositorios de charts y releases de Helm desde Dockerman.

Dockerman descarga y gestiona el binario de Helm en el primer uso, con verificación de checksum SHA-256. No hace falta instalar Helm por separado.

## Repositorios

Añade los repositorios que más uses y actualízalos cuando necesites el índice de charts más reciente.

<Steps>
  <Step>
    ### Añadir un repositorio

    Introduce un nombre y URL de repositorio, como Bitnami, Jetstack o ingress-nginx.
  </Step>
  <Step>
    ### Actualizar repositorios

    Actualiza el índice de charts después de añadir o modificar un repositorio.
  </Step>
  <Step>
    ### Eliminar un repositorio

    Elimina un repositorio cuando ya no lo necesites en Dockerman.
  </Step>
</Steps>

## Explorar charts

Busca en los índices añadidos y elige un chart. El navegador actual no promete un README integrado ni una lista completa de versiones.

## Instalar un release

<Steps>
  <Step>
    ### Elegir un chart y versión

    Elige el chart ofrecido y confirma la versión efectiva antes de instalar.
  </Step>
  <Step>
    ### Elegir nombre de release y namespace

    Fija el nombre del release y el namespace de destino antes de instalar.
  </Step>
  <Step>
    ### Editar values.yaml

    Dockerman carga los valores por defecto del chart en Monaco; tú sobrescribes solo los que necesitas.
  </Step>
  <Step>
    ### Instalar

    Inicia el release y espera el resultado. La UI no ofrece un stream continuo de progreso de Helm.
  </Step>
</Steps>

## Actualizar y revertir

<Steps>
  <Step>
    ### Abrir un release

    Abre el detalle del release para ver la revisión actual y el historial.
  </Step>
  <Step>
    ### Actualizar

    Edita values y la referencia disponible, luego actualiza. El formulario no promete un selector aparte de versión nueva.
  </Step>
  <Step>
    ### Revertir

    Elige una revisión anterior del historial y revierte a ella.
  </Step>
</Steps>

## Desinstalar un release

Elimina un release cuando ya no lo necesites en el clúster.

<Callout type="warn">
  La desinstalación elimina los recursos de Kubernetes creados por Helm, pero no siempre los PersistentVolumeClaims o CRDs que instaló el chart. Consulta la documentación del chart sobre `--keep-history` o `keepCRDs` antes de borrar un release en producción.
</Callout>
