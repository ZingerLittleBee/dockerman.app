---
title: "Hosts Remotos (SSH)"
description: "Gestiona hosts Docker remotos mediante túneles SSH y cambia entre ellos desde el selector de hosts."
---

Dockerman reenvía por SSH el socket Unix de un daemon Docker remoto. Las operaciones principales, los logs y los terminales funcionan mediante la API reenviada, pero las funciones dependientes del runtime no siempre coinciden con localhost. Por ejemplo, Dockerman no admite Compose con un destino Podman.

## Añade un host remoto

Añade un host una vez, luego cambia a él como cualquier otro objetivo Docker.

<Steps>
  <Step>
    ### Abre Hosts

    Abre la vista Hosts o el Selector de Hosts de la ventana principal.
  </Step>
  <Step>
    ### Haz clic en Añadir Host

    Haz clic en **Añadir Host**. Un diálogo solicitará los detalles de conexión.
  </Step>
  <Step>
    ### Completa los detalles SSH

    Introduce el host, puerto (predeterminado `22`), usuario y método de autenticación.
  </Step>
  <Step>
    ### Elegir preferencia de runtime

    Selecciona Auto, Docker o Podman. Auto sondea el host remoto y se conecta al socket del runtime que encuentre primero. El modo Podman descubre automáticamente los sockets rootless (`$XDG_RUNTIME_DIR/podman/podman.sock`) y rootful (`/run/podman/podman.sock`).
  </Step>
  <Step>
    ### Prueba y guarda

    Prueba la conexión, luego guárdala. Dockerman abre un túnel de prueba, sondea el runtime y muestra el tipo detectado.
  </Step>
</Steps>

## Autenticación por clave vs contraseña

Elige el método de autenticación SSH que coincida con la configuración del host remoto.

<Tabs items={['Clave SSH', 'Contraseña']}>
  <Tab>
    Pega la clave privada o selecciona un archivo. Dockerman lee y guarda el contenido de la clave, no solo la ruta.

    <Callout type="warn">
      La aplicación de escritorio actual guarda el contenido de la clave en la base de datos local mediante Base64 reversible. Base64 no es cifrado. Protege la cuenta local y el directorio de datos de la aplicación.
    </Callout>
  </Tab>
  <Tab>
    La contraseña también se guarda en la base de datos local mediante Base64 reversible. Úsala solo en un dispositivo y una cuenta de usuario de confianza.
  </Tab>
</Tabs>

## Cambia entre hosts

Usa el Selector de Hosts en la barra superior para moverte entre `localhost` y cada host remoto configurado. Cambiar de host recarga todos los datos para el objetivo seleccionado.

## Reconexión automática

Dockerman supervisa el túnel SSH y reintenta después de 3, 5 y 10 segundos. Si fallan todos los intentos, abre el diálogo de conexión fallida.

## Cómo funciona el túnel SSH

Dockerman abre una sesión SSH y reenvía un socket Unix local al socket del runtime remoto. El tráfico de la API Docker de ese host pasa por el túnel; el registro, las actualizaciones, los análisis y el resto del tráfico de la aplicación usan conexiones independientes.

## Notas de seguridad

<Callout type="warn">
  Configura solo hosts remotos en los que confíes y en redes de confianza. Las credenciales SSH permanecen en tu máquina local, así que trata el sistema que las almacena como sensible.
</Callout>
