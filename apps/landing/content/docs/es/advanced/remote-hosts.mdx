---
title: "Hosts Remotos (SSH)"
description: "Gestiona hosts Docker remotos mediante túneles SSH y cambia entre ellos desde el selector de hosts."
---

Dockerman reenvía mediante SSH el socket Unix de un daemon de Docker remoto. Las operaciones principales de Docker, los registros y los terminales funcionan a través de la API reenviada, pero las funciones que dependen del runtime o del host pueden diferir de las disponibles en `localhost`. Por ejemplo, Dockerman no admite Compose en destinos Podman.

## Añade un host remoto

Después de añadir un host, puedes cambiar a él como a cualquier otro destino Docker.

<Steps>
  <Step>
    ### Abre Hosts

    Abre la vista Hosts o utiliza el selector de hosts de la ventana principal.
  </Step>
  <Step>
    ### Haz clic en Añadir Host

    Haz clic en **Añadir Host** para abrir el cuadro de diálogo de conexión.
  </Step>
  <Step>
    ### Completa los detalles SSH

    Introduce los datos de conexión solicitados.
  </Step>
  <Step>
    ### Elige una preferencia de runtime

    Selecciona Auto, Docker o Podman. Auto busca sockets de runtime en el host remoto y se conecta al primero que encuentra. El modo Podman detecta automáticamente los sockets rootless (`$XDG_RUNTIME_DIR/podman/podman.sock`) y rootful (`/run/podman/podman.sock`).
  </Step>
  <Step>
    ### Prueba y guarda

    Prueba la conexión antes de guardar. Dockerman abre un túnel de prueba, detecta el runtime y muestra el tipo detectado.
  </Step>
</Steps>

## Cambia entre hosts

Usa el selector de hosts de la barra superior para cambiar entre `localhost` y cualquier host remoto configurado. Al cambiar de host, se vuelven a cargar los datos del destino seleccionado.

## Reconexión automática

Dockerman supervisa el túnel SSH y vuelve a intentarlo después de 3, 5 y 10 segundos. Si fallan todos los intentos, se abre el cuadro de diálogo de error de conexión.

## Cómo funciona el túnel SSH

Dockerman abre una sesión SSH y reenvía un socket Unix local al socket del runtime remoto. El tráfico de la API de Docker destinado a ese host pasa por el túnel. El registro, las actualizaciones, los análisis y el resto del tráfico de la aplicación utilizan conexiones independientes y no pasan por SSH.

## Notas de seguridad

<Callout type="warn">
  Configura únicamente hosts remotos de confianza y conéctate a ellos solo desde redes de confianza.
</Callout>
