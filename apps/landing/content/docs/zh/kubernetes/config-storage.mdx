---
title: "配置与存储"
description: "管理 ConfigMaps、Secrets、PersistentVolumeClaims 和 StorageClasses，少切 kubectl。"
---

用配置与存储查看工作负载依赖的数据源和底层存储。

## ConfigMaps

打开 ConfigMap 查看其键、值和 YAML。要改应用配置时编辑该对象。Dockerman 在保存前会检查资源版本，因此如果其他人在你编辑期间修改了同一 ConfigMap，你会收到冲突警告。不再需要时可以从列表中删除 ConfigMap。

<Callout type="info">
  编辑 ConfigMap 不会重启挂载它的 Pod。如果你需要新数据生效，请更新所属的 Deployment 或 StatefulSet。
</Callout>

## Secrets

打开 Secret 查看其类型、键和值。列表显示常见类型，如 `Opaque`、`kubernetes.io/tls` 和 `kubernetes.io/dockerconfigjson`。编辑时与 ConfigMaps 相同的资源版本冲突检测同样适用。

二进制 Secret 值可以下载到本地文件。不再需要时可以从列表中删除 Secret。

<Callout type="warn">
  显示操作会以明文展示 Secret 值。任何此时能看到屏幕的人都可以读取它们。
</Callout>

## PersistentVolumeClaims

用 PersistentVolumeClaims 查看每个声明的阶段、绑定的 PersistentVolume、存储类、访问模式和容量。声明已释放且不再需要时，可以从列表中删除 PVC。

## PersistentVolumes

除了上文的按声明视图外，PersistentVolume 也有专属页面。要独立于命名空间查看集群范围的存储时用它。

| 列 | 描述 |
| --- | --- |
| Name | PV 名称 |
| Capacity | 总容量 |
| Access modes | `RWO`、`ROX`、`RWX` 或 `RWOP` |
| Reclaim policy | `Retain`、`Delete` 或 `Recycle` |
| Status | `Available`、`Bound`、`Released` 或 `Failed` |
| Claim | 绑定的 `namespace/name` PVC（如果有） |
| StorageClass | 配置该卷的存储类 |

打开 PV 可查看其完整规格，包括底层卷源（CSI driver、hostPath、NFS 等）。

## StorageClasses

用 StorageClasses 查看集群的存储选项，包括供应程序、回收策略、卷绑定模式和默认类标记。

## Namespaces

Dockerman 还为 LimitRange、ResourceQuota 和 PodDisruptionBudget 提供单独页面。

Namespaces 页面可列出、创建和删除命名空间。删除命名空间可能移除其中的资源；界面不承诺复现 API 返回的每一条级联警告。
