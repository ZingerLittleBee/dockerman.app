---
title: "远程主机 (SSH)"
description: "通过 SSH 隧道管理远程 Docker 主机，并在主机选择器中切换。"
---

Dockerman 通过 SSH 转发远程 Docker 守护进程的 Unix socket。核心 Docker 操作、日志和终端可通过转发后的 API 工作，但依赖运行时或主机的功能不保证与本地完全一致，例如 Dockerman 不支持 Podman 目标的 Compose。

## 添加远程主机

只需添加一次主机，然后像切换其他 Docker 目标一样切换到它。

<Steps>
  <Step>
    ### 打开主机管理

    从主机视图或主窗口的主机切换器打开主机管理。
  </Step>
  <Step>
    ### 点击添加主机

    点击**添加主机**。对话框会要求输入连接详情。
  </Step>
  <Step>
    ### 填写 SSH 详情

    输入主机地址、端口（默认 `22`）、用户名和认证方式。
  </Step>
  <Step>
    ### 选择运行时偏好

    选择 Auto、Docker 或 Podman。Auto 模式会探测远程主机，并连接到首先发现的运行时 socket。Podman 模式会自动发现 rootless（`$XDG_RUNTIME_DIR/podman/podman.sock`）和 rootful（`/run/podman/podman.sock`）socket。
  </Step>
  <Step>
    ### 测试并保存

    测试连接，然后保存。Dockerman 会打开测试隧道、探测运行时并显示检测到的类型。
  </Step>
</Steps>

## 密钥认证与密码认证

选择与你远程主机配置相匹配的 SSH 认证方式。

<Tabs items={['SSH 密钥', '密码']}>
  <Tab>
    直接粘贴私钥或选择密钥文件。选择文件后，Dockerman 会读取并保存密钥内容，而不是只保留路径。

    <Callout type="warn">
      当前桌面应用使用可逆的 Base64 编码把私钥内容保存在本地应用数据库中。Base64 不是加密，请保护本地账户和应用数据目录。
    </Callout>
  </Tab>
  <Tab>
    密码同样使用可逆 Base64 编码保存在本地应用数据库中。只在你信任的设备和用户账户上使用。
  </Tab>
</Tabs>

## 切换主机

使用顶部栏的主机切换器在 `localhost` 和所有已配置的远程主机之间切换。切换主机会重新加载新选中目标的所有数据。

## 自动重连

Dockerman 会监控 SSH 隧道健康状态，并在 3、5、10 秒后依次重试。全部失败后会打开连接失败对话框。

## SSH 隧道工作原理

Dockerman 建立 SSH 会话，并将本地 Unix socket 转发到远程运行时 socket。该主机的 Docker API 流量通过隧道传输；Registry、更新、分析及其他应用流量是独立连接，不会经由 SSH 转发。

## 安全注意事项

<Callout type="warn">
  仅在受信任的网络上配置你信任的远程主机。SSH 凭据保存在本地机器上，因此请将存储它们的系统视为敏感设备。
</Callout>
