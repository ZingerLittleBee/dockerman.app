title: 通知
description: 通过 Telegram、ntfy、Gotify、Discord、Webhook 或系统通知接收告警。
---

Dockerman 可以通过多个渠道推送通知，人不在座位时也能知道发生了什么。渠道使用 **Shoutrrr 兼容的 URL 方案**，与 Watchtower、Beszel 和其他 homelab 工具使用的格式相同。

## 支持的渠道

| 渠道 | URL 格式 | 说明 |
| --- | --- | --- |
| Telegram | `telegram://token@telegram?chats=chat_id` | 从 BotFather 获取的 Bot token |
| ntfy | `ntfy://ntfy.sh/topic` 或 `ntfy://user:pass@ntfy.sh/topic` | 自托管或使用 ntfy.sh |
| Gotify | `gotify://gotify.example.com/token` | 自托管 Gotify 服务器 |
| Discord | `discord://token@id` | Webhook URL 转换为 Shoutrrr 格式 |
| Webhook | `generic://example.com/webhook` | 通用 JSON POST 到任意端点 |
| 系统通知 | 内置，无需 URL | macOS、Windows 和 Linux 原生通知 |

系统通知始终可用且默认启用。它们不计为"外部"渠道。

## 当前桌面支持范围

通知页面可以列出已配置渠道并发送测试通知。当前桌面 UI 尚未提供完整的添加、编辑、禁用或删除流程。底层通知适配器不能替代缺失的用户界面。

## 凭证安全

当前 daemon 会把完整的通知渠道 secret 写入 Dockerman 应用数据目录中的 `secrets/notification-channels.json`。在 Unix 上，Dockerman 会把文件权限限制为当前用户，但这些值不会存入系统 Keychain。

<Callout type="warn">
  请把 Dockerman 应用数据目录视为敏感数据。通用 webhook URL 可能在路径或查询参数中携带凭证，分享日志或诊断数据前请先检查。
</Callout>

## 通知的使用场景

通知渠道被两个系统使用：

<Cards>
  <Card title="告警规则" href="/zh/docs/homelab/alerts">
    每个告警规则绑定到一个或多个渠道。当规则触发时，它会广播到所有绑定的渠道。
  </Card>
  <Card title="镜像升级监控" href="/zh/docs/homelab/image-watches">
    镜像监控使用全局默认渠道列表。当发现新镜像版本时，所有默认渠道都会收到通知。
  </Card>
</Cards>

## 提示

- 如果你已经在 Watchtower 或 Beszel 中使用 Shoutrrr URL，可以将相同的 URL 粘贴到 Dockerman 中。
- 对于 Discord，将你的 webhook URL（`https://discord.com/api/webhooks/ID/TOKEN`）转换为 Shoutrrr 格式：`discord://TOKEN@ID`。
- 通用 webhook 渠道发送带有 `title` 和 `body` 字段的 JSON POST。使用它来集成任何接受 webhook 的服务。
