---
title: Getting Started
description: Install Dockerman and connect to a Docker or Podman runtime.
---

Install Dockerman, then connect to Docker or Podman. On Windows, to skip Docker Desktop, use the WSL2 path in the [Windows](/en/docs/platform/windows) platform guide.

## Prerequisites

<Callout type="info">
  A Docker or Podman runtime must be available before you can manage containers. Dockerman detects which runtime is running and adjusts the UI. On Windows, Dockerman can provision a Docker Engine through the WSL2 path in the [Windows platform guide](/en/docs/platform/windows).
</Callout>

## Install

<Tabs items={['macOS', 'Windows', 'Linux']}>
  <Tab>
    <Steps>
      <Step>
        ### Download the DMG

        Get the macOS DMG from the Download page.
      </Step>
      <Step>
        ### Open and drag to Applications

        Open the DMG, then drag Dockerman into Applications.
      </Step>
      <Step>
        ### Launch Dockerman

        Open it from Applications or Spotlight.
      </Step>
    </Steps>
  </Tab>
  <Tab>
    <Steps>
      <Step>
        ### Download the MSI

        Get the Windows MSI from the Download page.
      </Step>
      <Step>
        ### Run the installer

        Run the installer and follow the prompts.
      </Step>
      <Step>
        ### Launch Dockerman

        Open Dockerman, then use the WSL2 Setup Wizard on first launch if you want the built-in Docker Engine path. See the [Windows platform guide](/en/docs/platform/windows).
      </Step>
    </Steps>
  </Tab>
  <Tab>
    <Steps>
      <Step>
        ### Install the package

        Install the package that matches your distro. Use the `.deb`, `.rpm`, or AppImage build, then follow the [Linux platform guide](/en/docs/platform/linux).
      </Step>
      <Step>
        ### Add your user to the docker group

        Run:

        ```bash
        sudo usermod -aG docker $USER
        ```

        Log out and back in so the new group membership takes effect.
      </Step>
      <Step>
        ### Launch Dockerman

        Open Dockerman from your desktop menu. The published packages do not promise a GUI executable named `dockerman` on `PATH`.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## First launch

<Steps>
  <Step>
    ### The connect dialog

    Dockerman tries local Docker automatically and shows progress or errors.

  </Step>
  <Step>
    ### Pick a runtime source

    Choose the local socket, a TCP endpoint, or an SSH host. Set the runtime preference to Auto, Docker, or Podman. Auto detects whichever runtime is available, trying Docker first then Podman.
  </Step>
  <Step>
    ### Data initialization

    Dockerman loads containers, images, networks, volumes, and Compose projects in parallel.
  </Step>
  <Step>
    ### The dashboard

    Shows running and stopped containers, plus live charts.

  </Step>
</Steps>

## System requirements

| Platform | Minimum version | Architecture |
| --- | --- | --- |
| macOS | 11 (Big Sur) | Intel, Apple Silicon, Universal |
| Windows | Supported Windows 10 / 11 builds | x86_64 |
| Linux | Modern desktop distribution | x86_64 |

You need a Docker or Podman endpoint before you can manage containers. The project does not publish a minimum engine-version matrix. On Windows, Docker can come from the optional WSL2 path.
