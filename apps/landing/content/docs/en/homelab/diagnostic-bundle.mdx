A diagnostic bundle is a `.zip` of inspect data, events, logs, and stats for a container or Compose stack. Use it when filing an issue or debugging locally.

## What the bundle contains

<Files>
  <Folder name="diagnostic-bundle.zip" defaultOpen>
    <File name="manifest.json" />
    <File name="system.json" />
    <File name="events.json" />
    <Folder name="container-name" defaultOpen>
      <File name="inspect.json" />
      <File name="logs.txt" />
      <File name="stats.json" />
    </Folder>
  </Folder>
</Files>

| File | Contents |
| --- | --- |
| `manifest.json` | Generation timestamp, Dockerman version, host type, file inventory, redaction count, and any errors encountered |
| `system.json` | Docker version and system info. Registry usernames are cleared, but the file is not a general-purpose secret scrubber. |
| `events.json` | Docker events filtered by the selected time window and target containers |
| `inspect.json` | Combined container, image, network, and volume inspect data. Matching values in the container config's `Env` list are redacted by default. `State.Health` is included. |
| `logs.txt` | Timestamped container logs within the selected time window |
| `stats.json` | Resource usage samples from the time series store (raw 5-second samples when available, falling back to 5-minute aggregates for longer windows, or a current snapshot if time series data is not available) |

When targeting a Compose stack, the bundle includes one subdirectory per container in the stack.

## Generate a bundle

<Tabs items={['From a container', 'From a Compose stack', 'From Spotlight']}>
  <Tab>
    Open the container's action menu and select **Diagnostic bundle**.
  </Tab>
  <Tab>
    Open the Compose stack's overflow menu and select **Diagnostic bundle**.
  </Tab>
  <Tab>
    Open [Spotlight](/en/docs/advanced/spotlight) and search for "diagnostic bundle", then pick the target.
  </Tab>
</Tabs>

<Steps>
  <Step>
    ### Choose the time window

    Select how far back to include logs, events, and stats. Longer windows produce larger bundles.
  </Step>
  <Step>
    ### Review redaction settings

    Environment variables matching `TOKEN`, `PASSWORD`, `SECRET`, `KEY`, `CREDENTIAL`, or `AUTH` (case-insensitive) are replaced with `***REDACTED***` by default. Toggle this off if you need the raw values.
  </Step>
  <Step>
    ### Pick a save location

    Choose where to save the `.zip` file on your local filesystem.
  </Step>
  <Step>
    ### Wait for generation

    A progress indicator shows the packing status. Generation typically takes under 10 seconds for a single container.
  </Step>
  <Step>
    ### Open the result

    After generation, click **Show in Finder** (macOS) or the equivalent to jump to the saved file.
  </Step>
</Steps>

## Sensitive data redaction

By default, environment variable values that match the following pattern are replaced with `***REDACTED***`:

```
(?i)(TOKEN|PASSWORD|SECRET|KEY|CREDENTIAL|AUTH)
```

This applies to the `inspect.json` files in the bundle. You can disable redaction in the bundle dialog when you need the raw values for your own debugging.

<Callout type="warn">
  Redaction is intentionally narrow. Image environment values, labels, commands, mount paths, network and volume inspect data, and container logs can still contain secrets or private paths. Review every file before sharing a bundle.
</Callout>

## Tips

- Attach a diagnostic bundle when you open a GitHub issue or ask for help in a forum. The files are structured so others can inspect the same data you see.
- Stats in the bundle depend on the [background task scheduler](/en/docs/homelab/scheduler) having collected time series data. If the scheduler was recently enabled, the stats section may only contain a current snapshot.
- For Compose stacks with many containers, bundles can grow large. Use a shorter time window to keep the file size down.
