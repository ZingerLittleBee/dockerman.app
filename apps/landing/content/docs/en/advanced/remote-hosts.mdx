---
title: Remote Hosts (SSH)
description: Manage remote Docker hosts over SSH tunnels and switch between them from the host selector.
---

Dockerman connects to remote Docker daemons by forwarding their Unix socket over SSH. Core Docker operations, logs, and terminals work through the forwarded API, but runtime- and host-dependent features are not guaranteed to match localhost. Podman targets, for example, do not support Compose in Dockerman.

## Add a remote host

Add a host once, then switch to it like any other Docker target.

<Steps>
  <Step>
    ### Open Hosts

    Open the Hosts view or the Host Switcher in the main window.
  </Step>
  <Step>
    ### Click Add Host

    Click **Add Host**. A dialog asks for connection details.
  </Step>
  <Step>
    ### Fill in the SSH details

    Enter the connection details requested by the dialog.
  </Step>
  <Step>
    ### Choose a runtime preference

    Select Auto, Docker, or Podman. Auto probes the remote host and connects to whichever runtime socket it finds first. Podman mode discovers rootless (`$XDG_RUNTIME_DIR/podman/podman.sock`) and rootful (`/run/podman/podman.sock`) sockets automatically.
  </Step>
  <Step>
    ### Test and save

    Test the connection, then save it. Dockerman opens a test tunnel, probes the runtime, and shows the detected type.
  </Step>
</Steps>

## Switch between hosts

Use the Host Switcher in the top bar to move between `localhost` and every configured remote host. Switching hosts reloads all data for the newly selected target.

## Auto reconnect

Dockerman watches SSH tunnel health and retries after 3, 5, and 10 seconds. If all attempts fail, it opens the connection-failure dialog.

## How the SSH tunnel works

Dockerman opens an SSH session and forwards a local Unix socket to the remote runtime socket. The default is `/var/run/docker.sock` for Docker, or the detected Podman socket. Docker API traffic for that host flows through the tunnel. Registry, update, analytics, and other application traffic are separate and are not routed through SSH.

## Security notes

<Callout type="warn">
  Only configure remote hosts you trust on trusted networks.
</Callout>
