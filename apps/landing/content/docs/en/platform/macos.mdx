---
title: macOS
description: Run Dockerman on macOS with Docker Desktop, a compatible socket, or Apple Container.
---

Dockerman publishes one Universal DMG for macOS. Verify the current release asset and its signature on the release page before installation.

## Install

<Steps>
  <Step>
    ### Download the DMG

    Download the Universal DMG from the release page.
  </Step>
  <Step>
    ### Open and drag to Applications

    Open the DMG and drag Dockerman into Applications.
  </Step>
  <Step>
    ### Launch Dockerman

    Start Dockerman from Applications or Spotlight, then approve the first-launch prompt if macOS asks for it.
  </Step>
</Steps>

## Container backends

Dockerman can connect to Docker Desktop or another Docker-compatible socket. Set a custom socket path in Settings → Docker when automatic detection does not find it.

<Callout type="info">
  Docker-compatible sockets such as `/var/run/docker.sock` and `~/.docker/run/docker.sock` also work. If Dockerman does not detect your socket automatically, set the path in Settings → Docker settings.
</Callout>

On Apple Silicon with macOS 26 or later, Dockerman also exposes the Apple Container backend. Select **Apple Container** during engine onboarding or in Settings. It runs Linux containers in lightweight virtual machines and is not available on Intel Macs or older macOS versions.

## Menu bar and tray

Dockerman adds a menu bar icon for common application actions. In Settings → General, you can choose between the standard icon and the CPU/memory status style.

## Apple Silicon notes

On Apple Silicon, check the image platform before running a container. Many public images default to `amd64`, so use the `arm64` variant when available or set `--platform=linux/arm64` explicitly.

## Troubleshooting

- “Socket not found” means that Docker Desktop is not running or that Dockerman is using the wrong socket path.
- If Gatekeeper blocks Dockerman, right-click the app and choose **Open** the first time you launch it.
